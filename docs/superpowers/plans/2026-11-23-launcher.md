# Launcher DQIX Modern : plan de construction

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** un launcher (`game/dqix-launcher[.exe]`) qui met le jeu et le pack HD
à jour avant de jouer, avec deux barres, Nouveautés, Discord, langue, options
Classique / Moderne, et JOUER éteint tant que tout n'est pas installé.

**Architecture :** programme C séparé dans `launcher/`, SDL2 (`SDL_Renderer`) +
`runtime/stb_truetype.h` + `runtime/stb_image.h`, compilé par
`tools/build-game.sh` comme `hd-pack.exe`. La logique (ini, état, nouveautés,
lecture de progression) est dans des fichiers sans SDL, testés par
`tests/launcher/`. Il pilote des outils qui existent : `BUILD.bat`/`BUILD.sh`
(`DQIX_PROGRESS=1`), `hd-pack.exe`, `runtime/update.c`. `dqix` lancé sans
argument passe la main au launcher.

**Tech Stack :** C99, SDL2 2.0.14+ (`SDL_OpenURL`), stb, WinHTTP (Windows),
MSYS2 UCRT64 / gcc Linux, tests gcc + mingw/Wine en session cloud.

**Spec :** `docs/superpowers/specs/2026-11-23-launcher-design.md` (validée par
recompsmith le 2026-11-23). Maquette : v8 (hors dépôt, captures dans la PR).

## Review Focus

1. **Hors ligne / GitHub en erreur ou limité (403)** : jeu complet → JOUER
   allumé, « Hors ligne : mises à jour non vérifiées » ; jamais de blocage.
   → test `state_offline_complete_can_play` (tâche 2).
2. **Build qui échoue pendant une mise à jour** : barre Installation rouge avec
   la ligne `BUILD FAILED (...)`, JOUER éteint, RÉESSAYER relance, `update\previous`
   et `rollback.bat` sont là. → test `progress_build_failed_line` (tâche 3) et
   scénario cloud (tâche 9).
3. **Fermer le launcher pendant un téléchargement ou un build** : le prochain
   lancement reprend (le `.part` de `hd-pack.exe`, le build refait) ; aucun
   fichier à moitié copié n'est pris pour bon. → test `state_resume_after_kill`
   (tâche 2) + scénario cloud (tâche 9).
4. **`settings.ini` absent, vide, CRLF, clé en double ou sans `=`** : le
   launcher lit les valeurs par défaut et n'écrit que ses clés. → tests
   `ini_*` (tâche 2).
5. **Lancé par une ancienne install sans `game/dqix-launcher`, ou launcher qui
   ne démarre pas** : `dqix` démarre le jeu comme avant. → test
   `redirect_skips_when_missing` (tâche 7).

```c
/* settings.ini */
int  ini_get(const char* text, const char* key, char* out, size_t n);   /* 1 trouvé */
char* ini_set(const char* text, const char* key, const char* value);    /* nouveau texte (malloc), clé remplacée sur place ou ajoutée à la fin */
int  ini_load(const char* path, char** text);                           /* 0 si absent : *text = "" */
int  ini_save(const char* path, const char* text);                      /* écrit path.tmp puis renomme */

/* état : ce que l'écran montre et si JOUER est allumé */
typedef enum { ST_IDLE, ST_RUNNING, ST_DONE, ST_FAILED, ST_SKIPPED } StepState;
typedef struct {
    int platform_updates;     /* 1 sous Windows (updater + hd-pack.exe), 0 ailleurs */
    int online;               /* -1 inconnu, 0 hors ligne, 1 en ligne */
    int update_check;         /* settings.ini update_check (défaut 1) */
    int hd_pack_wanted;       /* hd_pack_download != 0 et mode = enhanced */
    int game_built;           /* game/dqix[.exe] et game/data/dqix.nds existent */
    int pack_complete;        /* textures/hd-pack/hd-pack.txt présent (pack tout ou rien) */
    char installed[32], available[32];   /* version.h locale, version distante ("" inconnue) */
    StepState update, build, pack;
} LState;
int  lstate_can_play(const LState* s);         /* voir règles ci-dessous */
const char* lstate_status_key(const LState* s); /* clé de texte de la ligne d'état */
const char* lstate_branch(const char* installed); /* "main" si "nightly" dans la version, sinon "stable" */

/* nouveautés */
typedef struct { char tag[24]; char date[11]; char title[160]; } NewsItem;  /* date "YYYY-MM-DD" ou "" */
int news_from_github(const char* json, NewsItem* out, int max);          /* champs tag_name, published_at, name ; brouillons et prereleases ignorés */
int news_title_from_notes(const char* md, char* out, size_t n);          /* première ligne non vide, « Dragon Quest IX Modern vX: » retiré */
int news_local(const char* notes_dir, const char* lang, NewsItem* out, int max); /* game/notes[/lang]/v*.md, triés avec update_newer, date "" */
```
Règles de `lstate_can_play` (spec) : faux si un pas est `ST_RUNNING` ou
`ST_FAILED` ; faux si `!game_built` ; si `hd_pack_wanted && platform_updates`,
vrai seulement si `pack_complete` ou si `online == 0` (hors ligne, on joue sans
le pack, il ne s'installe que complet) ; une mise à jour disponible et
`update_check` à 1 doit être faite d'abord, sauf `online == 0`.
`lstate_status_key` renvoie une des clés de la tâche 4 (`st_ready`,
`st_offline`, `st_updating`, `st_building`, `st_pack`, `st_failed`,
`st_no_updates_here`).

- Produces dans `runtime/update.h` (Windows ; ailleurs renvoie 0 avec un message) :

  `APPLY_BAT` (copie dans `update\previous` avec les mêmes exclusions, `tar -xf`

  --prepare "<jeu>\data\dqix.nds"` (ROM déjà copiée par le build précédent),
  lignes lues par `parse_build_line` → barre Installation ; un build est aussi
  lancé si `game_built` est faux ; 4) pack : si `hd_pack_wanted`,
  `hd-pack.exe --foreground` ; `hd-pack-status.txt` → la barre qui correspond.
  Linux : seulement la vérification et les nouveautés (`platform_updates = 0`).

  build qui a changé `game/dqix-launcher.exe`, le launcher se relance
